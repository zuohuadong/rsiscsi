# 本地缓存测量方法

## 安全边界

真实 NAS LUN 承载用户数据，只能执行 INQUIRY 和 READ。不要运行真实写基准，
不要启用真实写回，不要为了测量调用真实 SYNCHRONIZE CACHE。
所有写入、刷写失败、阈值与定时器验证使用 `127.0.0.1` 的独立内存 mock 目标；
新增缓存目标的可丢弃区域是每次新建的 8 MiB Vec；协议交错测试只使用临时内存
payload，不涉及磁盘、文件或远端 LUN。

固定工具链 `rust-toolchain.toml` 中的 1.100.0，设置
`export PATH="$HOME/.cargo/bin:$PATH"`。记录构建类型、请求大小、LBA 范围、QD、
预热和正式时长；一次只改变缓存配置，不把目标端热缓存当成本地命中。

## 自动与预设容量

- CLI 接受 `auto` / `off` / 显式大小。`read` 默认 `auto`；`bench` 与只读查询默认 `off`，
  保证原有吞吐对照仍是 LUN 速度。写回 `auto` 等于推荐值（自动读容量的 1/4，
  限制 64–256 MiB），且仍必须显式给出 `--allow-destructive-write`。
- 自动读容量 = 本机内存的 1/8，限制在 128 MiB–2 GiB，按 64 MiB 向下取整；
  macOS 用 `hw.memsize` 物理内存近似，Linux 用 `/proc/meminfo` 的 MemAvailable，
  都取不到时用 512 MiB。结果在进程内缓存一次，避免界面重复探测。
- GUI 读缓存默认「自动（推荐）」，写回默认关闭并预选「推荐（自动）」；
  下拉另有 64/128/256/512 MiB 与 1 GiB 档位，自动档旁标出推算的实际容量。
- 记录测量时同时写下最终容量。比较不同机器的自动值没有意义；
  同一台机器上改预设时一次只改一项。

## 只读验证

1. `rsiscsi inq` 确认目标、LUN、容量和逻辑块大小。WCE/RCD 是目标端策略，
   与客户端缓存开关分别记录。
2. 使用原有 `read` 命令读取相同的明确范围两次，分别输出到 `target/`；
   用 `cmp` 比较字节，避免提交 LUN 原始内容。
3. 开启 `--cache-size 1MiB`，对同一区域使用 `read --repeat 2`。
   请求字节偏移及长度必须是 65536 的整数倍，工作集不超过读缓存。
   首遍是 miss，第二遍应全命中，总计命中率 50%；不是声称每遍都是 50%。
4. 再用 `cmp` 与无缓存结果比较。确认 `dirty_bytes`、`flushes`、
   `write_bytes` 都是 0。独立进程之间不会保留缓存。

2026-11-15 实测：对既有文档目标 `10.1.10.1:3260`、LUN 1 执行只读检查，
INQUIRY 及 4 TiB / 512 B 容量读取成功。LBA 0、256 块的两份普通读取与
一份重复缓存读取均经 `cmp` 与 SHA-256 比对一致；
缓存统计 `hits=131072`、`misses=131072`，三个写相关字段全零。
临时结果只在被 git 忽略的 `target/cache-verify-*.bin`。
没有执行真实写入、写回、写入基准或缓存同步。

## 性能解释

分别测无缓存、冷缓存、工作集可容纳的重复读，以及大于容量的流式读；
只读 benchmark 沿用原有 `seq-read` / `rand-read`、`--bs`、`--qd`、
`--start-lba`、`--range-blocks`、`--warmup` 与 `--duration`。
保存 JSON 的 `cache` 与原吞吐/延迟字段，不改原有字段名。
统计是当前会话累计值，包含预热，不能当作仅正式测量阶段的命中率。

64 KiB 以下或非对齐读整条透传，不会通过扩读提高命中率。
需要读取大量唯一顺序段、工作集超预算或 NAS 后端限制时，低命中率不会提高
底层持续吞吐。命中内存后的数字是用户态缓存速度，不是 NAS/磁盘带宽。

写回 benchmark 的原吞吐字段反映请求返回速度，**不是持久化吞吐**；
`flush_seconds` 单独记录正式测量之后的同步耗时，不含周期/阈值触发的同步。
测试失败或取消时，GUI 保留脏数据和失败日志，不能以测试结束代替落盘证明。

## 确定性回归

```sh
cargo fmt --all
cargo build --workspace
cargo test --workspace
cargo clippy -p iscsi-core -p iscsi-cli --all-targets -- -D warnings
```

mock 断言包含 LRU 字节预算、命中命令计数、1 MiB 合并上限、非对齐透传、
各写接口的跨段失效、按 LBA 刷写、最终同步、失败留脏、默认关闭行为、
512/4096 字节逻辑块，以及阈值、定时器和 Logout。
还覆盖在途取消后的启用门禁、越界写回拒绝、配置变更与并发 group commit、
直接写之后不能错误复用旧同步凭据。

GUI 已实看 900×620 的默认「自动（推荐）」读缓存、写回关闭与红色警告、
未确认时的禁用状态，并检查无连接时的应用退出。macOS 选择器注册、返回类型和退出回调派发有独立
单元测试。带脏数据的完整 GUI 失败重试流程尚未进行交互式验收；
其底层保留/重试由 mock 验证，不能将此等同于完整 UI 流程实测。
